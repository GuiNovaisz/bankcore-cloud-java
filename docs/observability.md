# Observability

Spring Boot Actuator/Micrometer exports HTTP server/client latency, JVM/Hikari metrics, transfer request/completion/failure counters and latency, Ledger postings, outbox pending/publication failures, cache hit/miss/failure, consumer processing/failure and Resilience4j state. Metric labels are bounded to service, result, route, status and circuit name; no account/customer/transfer/idempotency/trace identifiers are labels.

Tracing uses Micrometer's OpenTelemetry bridge and OTLP HTTP exporter → Collector → Tempo locally. Spring's instrumented RestClient.Builder carries W3C trace context between services. Transfer persists parent trace and correlation id before asynchronous work, restores a child span around processing and propagates to Account/Ledger. Ledger records its current parent in the outbox in the financial transaction. Publisher restores that parent, creates an outbox.publish span and injects context into SQS message attributes. Projection restores it for projection.process. Ledger emits a ledger.db.work span and timer around SQL work; this is an application DB-work span, not automatic per-query JDBC instrumentation or a measurement of the outer transaction's final commit.

Structured JSON logs include timestamp, level, service, logger, traceId/spanId and correlationId while a request/work scope is active; business actions add action/outcome. Framework/startup lines may have no operation context. Financial journal history and replay/reconciliation audits are persisted separately from diagnostic logs. Credentials, Authorization headers and full request/event payloads are never logged by application code. Nginx logs the fixed operator/service username and request path, not Authorization values.

Grafana BankCore Overview is provisioned as JSON with request/error rates, p95, throughput/failures, service health, DB connections, outbox, cache, breaker and consumer failures. DB-work latency is available as ledger_db_latency_seconds; HTTP client latency exposes remote dependencies. Tempo trace-id query is used by B15/B16 and the verified trace JSON is saved as an artifact. No invented screenshot is provided.

Prometheus alert rules cover errors, latency, backlog, consumer failures and service unavailability. Local DLQ is asserted through the actual queue API by B9; AWS has a CloudWatch DLQ-count alarm and queue-age alarm. No synthetic claim that a CloudWatch metric exists locally. AWS logs go to per-task awslogs groups, tracing via a private Collector with X-Ray exporter. CloudWatch native ECS/RDS/SQS/ALB metrics and alarms complement application metrics. Exporting custom Prometheus metrics to CloudWatch is an explicit future ADOT/EMF configuration extension, not claimed deployed.

Liveness is application process availability. Readiness includes DB for the owning service; Redis and SQS are deliberately excluded because acceptance/financial processing can operate safely with backlog/cache bypass. A worker's DB readiness does not mean SQS is healthy; queue metrics and failure counters cover that separately.
